# S2: Recommend pipeline (built without working YouTube)

Goal: the full `recommend` server action, written against injectable dependencies so every step and every fallback is unit-tested with fakes today, and only the thin adapters touch YouTube/LLM.

**Files owned (under ``):** `src/recommend/*` (new), `src/actions/recommend.ts`, `src/actions/index.ts`, `src/integrations.ts`.

**In scope (enumerated):**
1. Input validation (Zod) of `CheckinInput`.
2. Crisis gate: deterministic phrase check on the note, plus the LLM `needsSupportResources` flag. Either one returns `status:'support'`, stores the check-in **without** the note, skips recommendations.
3. Per-user daily cap (UTC day, `DAILY_CAP = 12` runs) using the `usage` collection.
4. Hard filter (S1) → LLM "interpret" (Zod-validated, ids checked against the filtered set) → retrieval per activity (curated query, 24h cache in `searchCache`, details for duration) → LLM "rank and explain" (ids checked against real candidates) → 2–3 picks.
5. Deterministic fallbacks: interpret, rank, and video each degrade independently; `no_video` when nothing can be retrieved; `nothing_fits` when the filter empties.
6. Copy guard: model text containing a URL or a forbidden word is replaced by template text.
7. Persistence: `checkins` + `suggestions` rows, always scoped to the caller's `userId` (server actions run with RBAC off).
8. Billing: `youtube` and `anthropic` set to `user` in `src/integrations.ts`.

**Out of scope:** any UI, preferences editing UI, cron refresh, calendar/weather, deploy.

**Acceptance (automated):** `npm run type-check`; `npm run test:unit` covering: happy path, hallucinated activity/video ids dropped, garbage/invalid LLM output, LLM failure, URL/forbidden-word replacement, duration filter, cache hit skips YouTube, YouTube failure → `no_video`, nothing fits, cap, crisis (keyword and LLM flag, note not stored), re-run uses exclusions, foreign `checkinId` ignored.
**Acceptance (manual, Elena):** review the crisis phrase list and the prompts' wording (`src/recommend/safety.ts`, `prompts.ts`).

**What these checks do NOT prove:** that the real Anthropic response has the assumed shape (`extractText` is tolerant but unverified: needs one cheap real call); that real YouTube results have the assumed fields (`normalizeVideo` is tolerant but unverified, and YouTube is currently failing upstream); that `get-video-details` accepts several comma-joined ids; real latency; that the crisis phrase list catches everything (it will not; it is a first layer, not a guarantee); real per-record RBAC isolation (needs two live accounts).

**Risks / stop conditions:** if the real LLM response or YouTube fields differ from the tolerant parsers, fix the parsers from the real output, not by guessing. Never retry a failed paid call automatically (a failed YouTube call was still charged).

**Data flow to note for the UI (S3/S6):** the optional note text is sent to the LLM provider through DeepSpace. The UI should say so near the note field.
